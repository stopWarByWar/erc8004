# ERC-8183 Job API Spec（Job Detail / Job List / Jobs General / Charts）

本文面向后端 API 开发与前端联调，定义 Job Detail 与 Job List（含 Jobs General 顶部概览、5.4 图表体系）所需接口的 **参数、默认值、返回结构、枚举与示例**。

设计基线：[docs/designs/202604101000_erc8183-job.md](../../../designs/202604101000_erc8183-job.md) 第 5 章。

实现参考（当前仓库）：

- Router：`server/api/router.go`
- Handler/Logic（Commerce 既有接口风格）：`server/api/handle/commerceHandle.go`、`server/api/logic/commerceLogic.go`
- Model：`model/commerce.go`（`GetCommerceJobs`、`GetCommerceJobByID`）
- 快照表：`commerce_jobs`
- 证据表：`commerce_actions`（时间线/事件表由其提供）

> 注意：本项目接口统一使用 JSON 包装层（成功/失败均 HTTP 200）：成功 `code=0,status=success`；失败 `code=1,status=failed,msg=...`。该约定与现有 `docs/specs/backend/202604071929_erc8183-ui-api.md` 一致。

---

## 0. 约定与通用规则

### 0.1 Job 唯一定位键

- `chain_id`（string）
- `commerce_contract`（string，合约地址）
- `job_id`（uint64）

### 0.2 Job 状态枚举（`status`）

- `open`
- `funded`
- `submitted`
- `completed`
- `rejected`
- `expired`

### 0.3 时间

所有时间均为 **unix 秒**（uint64），且必须是 on-chain 时间：

- 列表排序与“Last Updated”使用 `commerce_jobs.updated_at`
- 事件证据使用 `commerce_actions.block_timestamp`

### 0.4 分页

- `page`：默认 `1`，\(\le 0\) → `1`
- `page_size`：默认 `20`，\(\le 0\) → `20`，\(\gt 100\) → `100`

### 0.5 金额与 USD

- `budget_usd`：BudgetSet 时刻的历史 USD（非实时）
- `paid_amount_usd/platform_fee_usd/evaluator_fee_usd`：结算事件时刻的历史 USD
- UI 展示规则：`status != completed` 时 paid/fee 建议展示 `—`（避免误读为 0）

## 1. GET `agent/commerce/jobs`（Job List）

用于 Job Browser 的列表页，以及（可选）Agent detail 下的 job 列表（通过 role/counterparty 组合实现）。

### 1.1 Query 参数

- **过滤**
  - `chain_id`（string，可选）
  - `commerce_contract`（string，可选）
  - `status`（string，可选，见 0.2）
  - `token_symbol`（string，可选）
  - `payment_token`（string，可选）
  - `min_budget`（float64，可选）
  - `max_budget`（float64，可选）
  - `min_budget_usd`（float64，可选）
  - `max_budget_usd`（float64，可选）
  - `start_time`（uint64，可选）：`updated_at >= start_time`
  - `end_time`（uint64，可选）：`updated_at <= end_time`

- **角色视角（用于 agent detail job list，可选）**
  - `role`（string，可选）：`client|provider|evaluator`
  - `agent_address`（string，可选）：在 role 对应字段上过滤
  - `counterparty`（string，可选）：对手方地址（与 role 联动；例如 role=provider 时对手方=client）

- **排序**
  - `sort_by`（string，可选）：
    - `updated_at`（默认）
    - `budget_usd`
    - `paid_amount_usd`
  - `sort_order`（string，可选）：`desc`（默认）/`asc`

- **分页**
  - `page`（int，可选）
  - `page_size`（int，可选）

### 1.2 返回结构

```json
{
  "code": 0,
  "status": "success",
  "msg": "",
  "data": {
    "jobs": [
      {
        "chain_id": "84532",
        "commerce_contract": "0x...",
        "job_id": 1,
        "status": "funded",
        "updated_at": 1744560000,

        "client": "0x...",
        "provider": "0x...",
        "evaluator": "0x...",

        "payment_token": "0x...",
        "token_symbol": "USDC",
        "budget": 12.34,
        "budget_usd": 12.34,

        "paid_amount": 0,
        "paid_amount_usd": 0,
        "platform_fee_amount": 0,
        "platform_fee_usd": 0,
        "evaluator_fee_amount": 0,
        "evaluator_fee_usd": 0
      }
    ],
    "total": 123
  }
}
```

### 1.3 与 Job List UI 的最小对齐

- 定位：`chain_id` + `commerce_contract` + `job_id`
- 状态：`status`
- 金额：`token_symbol` + `budget`（小字 `budget_usd`）
- 结算：`paid_amount_usd`（仅 completed；否则前端展示 `—`）
- 时间：`updated_at`（默认排序）
- 角色视角：由 query 端（role/agent/counterparty）决定是否展示

### 1.4 校验与错误

- `status/role/sort_by/sort_order` 传了但非法 → `Invalid Request`
- `start_time/end_time` 非 uint64 → `Invalid Request`
- `min/max` 非数字（NaN/Inf）→ `Invalid Request`
- DB/内部异常 → `Internal Error`

## 3. GET `agent/commerce/jobs/general`（Jobs General：Summary Bar + Distribution）

为 Job List 顶部 “Jobs General 信息”提供后端聚合结果；**指标随筛选变化**，并与列表同一过滤条件。

### 3.1 Query 参数

与 `GET agent/commerce/jobs` 完全一致（同一套 filters），额外：

- `include_distributions`（bool，可选，默认 true）：是否返回 Distribution Row（P1）

### 3.2 返回结构

```json
{
  "code": 0,
  "status": "success",
  "msg": "",
  "data": {
    "summary": {
      "jobs_count": 0,
      "paid_volume_usd": 0,
      "budget_volume_usd": 0,
      "outcome_mix": {
        "completed": 0,
        "rejected": 0,
        "expired": 0
      },
      "active_mix": {
        "open": 0,
        "funded": 0,
        "submitted": 0
      },
      "last_updated": 0
    },
    "distributions": {
      "token": [
        { "token_symbol": "USDC", "jobs_count": 0, "budget_volume_usd": 0, "paid_volume_usd": 0 }
      ],
      "chain_contracts": [
        {
          "chain_id": "84532",
          "chain_name": "Base Sepolia",
          "chain_logo": "https://...",
          "erc8183_contracts": [
            {
              "commerce_contract": "0x...",
              "jobs_count": 0,
              "budget_volume_usd": 0,
              "paid_volume_usd": 0,
              "drilldown": { "chain_id": "84532", "commerce_contract": "0x..." }
            }
          ]
        }
      ],
      "fees": {
        "platform_fee_usd": 0,
        "evaluator_fee_usd": 0
      }
    }
  }
}
```

### 3.3 聚合口径（与 design 对齐）

- `paid_volume_usd = SUM(paid_amount_usd)`（仅 completed 有意义；未完成通常为 0）
- `budget_volume_usd = SUM(budget_usd)`
- `last_updated = MAX(updated_at)`
- `outcome_mix`：按 `status in (completed,rejected,expired)` 计数
- `active_mix`：按 `status in (open,funded,submitted)` 计数

## 3.5 GET `agent/commerce/jobs/filters`（Job Browser Filters 默认选项）

用于前端 FiltersPanel 的默认选项（链/合约/token）。后端会定时从 DB 拉取去重值并缓存到内存；请求时直接读内存，避免每次点开筛选都打 DB。

### 3.5.1 Query 参数

- 无（P0）

### 3.5.2 返回结构

```json
{
  "code": 0,
  "status": "success",
  "msg": "",
  "data": {
    "filters": {
      "chains": [
        { "chain_id": "8453", "chain_name": "Base", "chain_logo": "https://..." }
      ],
      "commerce_contracts": [
        "0x1111111111111111111111111111111111111111"
      ],
      "payment_tokens": [
        "0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48"
      ],
      "last_updated": 1713000600
    }
  }
}
```

### 3.5.3 缓存策略（实现约定）

- 定时刷新：每 5 分钟从 `commerce_jobs` 做 `DISTINCT` 刷新一次
- 兜底：缓存未初始化时，首次请求会同步拉取一次

## 4. GET `agent/commerce/jobs/charts`（5.4 图表数据）

提供 5.4 “Charts Gallery”所需的聚合数据。图表输出均应支持 **drill-down**：前端通过返回的 `drilldown` 对象构造 Job List 或 Activity Feed 的 filters。

### 4.1 Query 参数

与 `GET agent/commerce/jobs` 同一套 filters，额外：

- `window`（string，可选）：`24h|3d|7d|1month|all|custom`（默认 `7d`）
- `bucket_seconds`（uint64，可选）：custom 时必填

window 默认分桶建议（当未显式传 `bucket_seconds` 时）：

- `24h` → 3600（1h）
- `3d` → 10800（3h）
- `7d` → 21600（6h）
- `1month` → 86400（1d）
- `all` → 86400（1d）

### 4.3 口径说明

- 时间桶使用 on-chain `updated_at` 或 actions 的 `block_timestamp`（视图表类型）：

  - Actions Over Time 若需要 action 粒度，建议走 `commerce_actions`（更准确）
- `created_jobs_over_time`：基于 `commerce_actions` 的 `JobCreated`，按 `block_timestamp` 分桶计数（表示“新增 jobs”）。
- `unique_clients_over_time / unique_providers_over_time`：基于 `commerce_jobs`，按 `updated_at` 落桶后，对 `client/provider` 做 distinct 计数。
- `platform_fee_usd_over_time`：基于 `commerce_actions` 的 `PlatformFeePaid.amount_usd`（历史 USD）按 `block_timestamp` 分桶 SUM（表示“当期发生额”，而不是快照字段）。
- `fees_breakdown`：`SUM(platform_fee_usd)` 与 `SUM(evaluator_fee_usd)`（通常仅 completed 有意义）
- `budget_histogram_usd`：基于 `budget_usd` 做区间分桶

## 5. 失败与校验（统一）

### 5.1 参数非法（`Invalid Request`）

- `job_id` 非 uint64
- `status` 非枚举
- `role` 非枚举
- `sort_by/sort_order` 非枚举
- `start_time/end_time` 非 uint64
- `window` 非枚举；`window=custom` 但缺 `bucket_seconds`

### 5.2 内部异常（`Internal Error`）

- DB 查询失败
- 聚合超时/不可用（可在实现阶段加入超时与降级）

## 6. 联调 Checklist（API）

- [ ] `GET agent/commerce/jobs` 支持 status/token/金额/时间过滤，且 `updated_at` 为 on-chain
- [ ] `GET agent/commerce/jobs/detail` 返回 job 快照字段齐全（含 paid/fee 拆分与 usd）
- [ ] `GET agent/commerce/jobs/general` 的 summary 与 list filters 完全同口径（指标随筛选变化）
- [ ] `GET agent/commerce/jobs/charts` 返回 drilldown 可用于回填到 list filters（可复制分享）
