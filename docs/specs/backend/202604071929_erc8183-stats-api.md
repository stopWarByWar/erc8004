# ERC-8183 Commerce Stats API Spec

本文定义 `GET /agent/identity/commerce/stats` 接口的参数、返回结构与行为准则。

设计基线：`docs/designs/202604081000_erc8183-stats.md`

---

## 1. 端点

**路径**：`GET /agent/identity/commerce/stats`

---

## 2. Query 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `uid` | uint64 | 是 | Agent UID |

**错误处理**：
- `uid` 非法（无法解析为 uint64）→ HTTP 200，`code=1`，`msg="Invalid Request"`

---

## 3. 返回结构

```json
{
  "code": 0,
  "status": "success",
  "data": {
    "stats": {
      "action_breakdown": { ... },
      "time_series": { ... },
      "budget_distribution": { ... }
    }
  }
}
```

### 3.1 `action_breakdown`

按 role 分组的 action 计数。无数据的 role 直接省略（不返回该 key）。

```json
{
  "action_breakdown": {
    "provider": {
      "job_created": 10,
      "job_funded": 8,
      "job_submitted": 6,
      "job_completed": 5,
      "job_rejected": 1,
      "job_expired": 0
    },
    "client": { ... },
    "evaluator": { ... }
  }
}
```

- Key：`provider` / `client` / `evaluator`
- Value：`ActionCounts`（6 个 action 的 count）
- 无数据 role 不出现

### 3.2 `time_series`

三个时间窗口，各返回 `TimeBucket` 数组。无数据的桶不出现。

```json
{
  "time_series": {
    "24h": [
      {
        "bucket": 1744124400,
        "completed_count": 3,
        "rejected_count": 0,
        "success_rate": 1.0
      }
    ],
    "7d": [...],
    "30d": [...]
  }
}
```

**窗口定义**：

| 窗口 | 时间范围 | 桶大小 | 桶数量 |
|------|---------|--------|--------|
| `24h` | now - 86400s ~ now | 3600s（1 小时） | 最多 24 |
| `7d` | now - 604800s ~ now | 21600s（6 小时） | 最多 28 |
| `30d` | now - 2592000s ~ now | 86400s（1 天） | 最多 30 |

**字段定义**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `bucket` | int64 | Unix timestamp（桶起始时间） |
| `completed_count` | int | 该桶内 `job_completed` 数量 |
| `rejected_count` | int | 该桶内 `job_rejected` 数量（不含 `job_expired`） |
| `success_rate` | float64 | `completed / (completed + rejected)`，`completed + rejected = 0` 时为 0 |

**当前时间（now）**：
- 优先：该 agent 在 `commerce_actions` 表中最新一条记录的 `block_timestamp`
- 若该 agent 尚无任何 action：fallback 到系统时间 Unix timestamp

> 说明：fallback 行为与当前 handler 实现保持一致。

### 3.3 `budget_distribution`

按 role + commerce_contract 分组，token 单位问题由前端处理（contract 地址作为 token proxy）。

```json
{
  "budget_distribution": {
    "provider": {
      "0x123...abc": {
        "total_count": 50,
        "buckets": {
          "small":  { "count": 20, "max_amount": "1000" },
          "medium": { "count": 20, "max_amount": "5000" },
          "large":  { "count": 10, "max_amount": "50000" }
        }
      }
    }
  }
}
```

**分桶逻辑（百分位数）**：

以该 agent + 该 contract + 该 role 的终态 job（`action IN ('job_completed','job_rejected')`，不含 `job_expired`）的 `job_budget` 样本为基准：

- **small**：budget < 33rd percentile
- **medium**：33rd percentile <= budget < 66th percentile
- **large**：budget >= 66th percentile

若样本量 < 3：不拆分，直接返回一个 unnamed 桶（仅有 `count` 和 `max_amount`，无 small/medium/large 层级）。

若某桶 count = 0，该桶不出现。

`max_amount` 为该桶内最大 budget 值，string 格式（避免浮点精度问题）。

**注意**：不同 contract 对应不同 token，budget 原始值不可直接比较。前端负责 token 汇率换算。

---

## 4. 错误返回

- `uid` 非法：`code=1`，`msg="Invalid Request"`
- DB / 内部异常：`code=1`，`msg="Internal Error"`

---

## 5. 空状态行为

| 场景 | 行为 |
|------|------|
| 某 role 无 action | `action_breakdown` 不出现该 role |
| 某时间窗口无数据 | 数组为空 `[]` |
| 某 contract 下某桶 count=0 | 该桶不出现 |
| agent 无任何 commerce_actions | `action_breakdown = {}`，`time_series` 三窗口均为空数组，`budget_distribution = {}` |

## 7. 与其他接口的关系

| 接口 | 用途 |
|------|------|
| `GET /agent/identity/commerce/stats` | **本文** — 图表统计 |
| `GET /agent/identity/commerce/scores` | 权威聚合分数（provider/client/evaluator 各 score） |
| `GET /agent/identity/commerce/actions` | 行为明细列表（分页/过滤） |
| `GET /agent/identity/detail` | 含 `commerce_score` 便捷摘要 |

`commerce/stats` 与 `commerce/scores` 口径一致（均基于 `commerce_actions`），不依赖 `commerce_scores` / `commerce_scores_global` 表。

---

## 8. 联调 Checklist

- [ ] `GET /agent/identity/commerce/stats?uid=X` 返回 HTTP 200，JSON 结构符合本文定义
- [ ] `action_breakdown`：无数据的 role 不出现，6 个 action 字段均存在（evaluator 固定返回 0）
- [ ] `time_series`：三个窗口（24h/7d/30d）均存在，bucket 升序排列
- [ ] `time_series.success_rate`：`rejected_count` 仅统计 `job_rejected`（不含 expired），两者为 0 时为 0
- [ ] `budget_distribution`：按 contract 分组，桶内 max_amount 非递减
- [ ] `budget_distribution`：样本量 < 3 时不拆分 small/medium/large，直接返回 count + max_amount
- [ ] `uid` 传非数字时返回 `code=1，msg="Invalid Request"`
- [ ] uid 无数据时：`action_breakdown={}`，`time_series` 三窗口空数组，`budget_distribution={}`
