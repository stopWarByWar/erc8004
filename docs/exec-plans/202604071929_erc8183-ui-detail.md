## 0. 范围与验收口径

- [x] **UI 需要的每一列**（时间/Job/行为/信号/金额/对手方/前序状态/Hook/Tx）在 `commerce_actions` 都有对应字段，且由 Indexer 在合适事件写入。
- [x] `GET agent/identity/commerce/actions` 支持第 8.4~8.7 的过滤与 8.7 的排序，分页稳定。
- [x] `GET agent/identity/commerce/scores` 返回 0~3 个 role 的 score（role 维度），无数据时返回空数组或空对象但结构稳定。
- [x] Indexer 出现临时 RPC 错误（`getJob` 失败、节点抖动）不会永久卡死在同一条 log 上。`getJobWithRetry` 有 3 次重试，`isRetryable` 区分可重试错误，永久错误跳过该 log。
- [x] 写入幂等（重复扫链/重启/回放不会产生重复行），`CreateCommerceAction` 使用 `ON CONFLICT DO NOTHING`。

## 1. 展示列 ↔ DB 字段 ↔ 链上事件映射（alignment matrix）

> 说明：这是“展示字段是否能被索引出来”的最小真相表。若本表中某行“链上事件/handler”为空，意味着 UI 要展示但 indexer 并未生产该字段，需要补齐。

### 1.1 通用列

| UI 列名 | `commerce_actions` 字段 | 生产来源（事件 / handler） | 状态 |
|---|---|---|---|
| 时间 | `block_timestamp` | 所有事件写入时从 log 取 | ✅ |
| Job | `job_id` + (`chain_id`,`commerce_contract`) | 所有事件 | ✅ |
| 行为 | `action` | 事件类型映射 | ✅ |
| 信号 | `signal_polarity`,`signal_weight` | `DetermineSignal(action, previous_status, role)` | ✅ |
| 金额 | `job_budget` | `JobFunded`/终态(`getJob`) | ✅ |
| 对手方 | `counterparty` | 终态 fan-out（Provider→Client, Client→Provider, Evaluator→Provider） | ✅ |
| 前序状态 | `previous_status` | `JobCompleted/Rejected/Expired`（由 `inferPreviousStatus*` 推断） | ✅ |
| Hook | `hook_address` | `JobCreated`/`JobFunded`/`JobSubmitted` 均有 `tryGetHookAddress` | ✅ |
| Tx | `tx_hash` | 所有事件 | ✅ |

### 1.2 Role 维度：事件覆盖（按设计第 8 章）

| Role | UI 期望行为（最小集合） | 链上事件 | 状态 |
|---|---|---|---|
| provider | `job_submitted`, `job_completed`, `job_rejected`, `job_expired` | `JobSubmitted`, `JobCompleted`, `JobRejected`, `JobExpired` | ✅ 已有（终态通过 fan-out） |
| client | `job_created`, `job_funded`, `job_completed`, `job_rejected`, `job_expired` | `JobCreated`, `JobFunded`, `JobCompleted`, `JobRejected`, `JobExpired` | ✅ 已有（created/funded 独立写入） |
| evaluator | `job_completed`, `job_rejected`, `job_expired` | `JobCompleted`, `JobRejected`, `JobExpired` | ✅ 已有（终态通过 fan-out） |

### 1.3 合约 ABI 额外事件（候选：用于”时间线审计”）

来自 `abi/AgenticCommerce.json`：

| 事件 | UI 是否需要展示 | 状态 | 备注 |
|---|---|---|---|
| `ProviderSet` | 未决定 | ⚠️ 索引器已解析（`handleProviderSet`），但不写 `commerce_actions` | 若展示”谁改了 provider”需单独处理 |
| `BudgetSet` | 未决定 | ⚠️ 索引器已解析（`handleBudgetSet`），但不写 `commerce_actions` | 若展示”预算调整”需单独处理 |
| `PaymentReleased` | 本期默认不纳入 | N/A | — |
| `Refunded` | 本期默认不纳入 | N/A | — |
| `EvaluatorFeePaid` | 本期默认不纳入 | N/A | — |
| `HookWhitelistUpdated` | 通常不进 agent 时间线 | N/A | — |

## 2. Indexer（CommerceProcessor）清单

目标文件：`indexer/processor/commerce.go`

- [x] **事件 topic 订阅**：8 个 event topics 已注册（JobCreated, JobFunded, JobSubmitted, JobCompleted, JobRejected, JobExpired, ProviderSet, BudgetSet）
- [x] **字段补全**：所有终态事件通过 `tryGetHookAddress` 获取 hook（3 次重试 + `isRetryable` 分类）
- [x] **幂等写入**：`CreateCommerceAction` 使用 `ON CONFLICT DO NOTHING`，唯一约束兜底
- [x] **RPC/游标可靠性**：`getJobWithRetry` 3 次重试 + 指数退避；永久错误跳过 log（不卡死）
- [x] **状态推断**：`inferPreviousStatusForRejected` / `inferPreviousStatusForExpired` 逻辑覆盖 rejected/expired 路径
