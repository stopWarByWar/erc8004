# ERC-8183 Job API 执行清单（Job Detail / Job List / Jobs General / Charts）

> 设计基线：`docs/designs/202604101000_erc8183-job.md`（第 5 章）
> Spec 基线：`docs/specs/backend/job/202604131905_erc8183-job-api.md`

本文是 Job Browser/Detail 对应后端 API 的落地清单（按项目现有 handler/logic/model 分层风格）。

---

## 0. 验收口径

- [x] `GET agent/commerce/jobs`：
  - [x] 支持 status/token/金额/时间过滤
  - [x] 默认按 `updated_at DESC`
  - [x] 返回 `total`
  - [x] `updated_at` 为 on-chain（来自 `commerce_jobs.updated_at`）
- [x] `GET agent/commerce/jobs/detail`：
  - [x] 返回单个 job 快照字段齐全（含 paid/fee 拆分与 usd）
  - [x] `budget_usd`/`paid_amount_usd`/`platform_fee_usd`/`evaluator_fee_usd` 语义正确
- [x] `GET agent/commerce/jobs/general`：
  - [x] Summary Bar 指标随 filters 变化
  - [x] `last_updated = MAX(updated_at)`
  - [x] outcome_mix / active_mix 计数口径正确
- [x] `GET agent/commerce/jobs/charts`：
  - [x] 输出包含 drilldown 对象，可回填为 list filters（可复制分享）
  - [x] 时间桶与金额聚合口径符合 spec
- [x] 参数非法统一返回 `code=1,msg="Invalid Request"`；内部异常返回 `code=1,msg="Internal Error"`

## 3. Model 层（查询与聚合）

目标文件：`model/commerce.go`

### 3.1 Job List 查询

- [x] `GetCommerceJobs(q CommerceJobsQuery) ([]CommerceJob, total int64, err error)`
  - [x] WHERE filters：status/token/金额/时间
  - [x] 分页：page/page_size
  - [x] 排序：`updated_at/budget_usd/paid_amount_usd` + order
  - [x] 稳定性：二级排序补 `job_id`（翻页稳定）

### 3.2 Job Detail 查询

- [x] `GetCommerceJobByID(chainID, contract string, jobID uint64) (*CommerceJob, error)`
  - [ ] not found → 返回可区分错误（handler 映射为 Internal 或业务 404 策略，按项目约定）

### 3.3 Jobs General 聚合（P0）

新增函数（建议单独函数，避免塞到 logic）：

- [x] `GetCommerceJobsGeneral(q CommerceJobsQuery) (summary, distributions, error)`
  - [x] `jobs_count = COUNT(*)`
  - [x] `paid_volume_usd = SUM(paid_amount_usd)`
  - [x] `budget_volume_usd = SUM(budget_usd)`
  - [x] `last_updated = MAX(updated_at)`
  - [x] `outcome_mix`：按 status in (completed,rejected,expired)
  - [x] `active_mix`：按 status in (open,funded,submitted)
  - [x] distributions：
    - [x] token：按 `token_symbol` group
    - [x] chain_contracts：按 `chain_id` 分组，内部 `erc8183_contracts` 按 `commerce_contract` 聚合
    - [x] fees：`SUM(platform_fee_usd)` / `SUM(evaluator_fee_usd)`

### 3.4 Charts 聚合（P1~P2，可按 include 分阶段）

- [x] `GetCommerceJobsCharts(...)`（当前为 P0 snapshot 版本）：
  - [x] Active Jobs Over Time（按 `commerce_jobs.updated_at` 分桶）
  - [x] Paid Volume Over Time（按 `paid_amount_usd` 分桶，drilldown 默认带 `status=completed`）
  - [x] Outcome Mix / Funnel（按 status 聚合）
  - [x] Token/ChainContract 分布（group by）
  - [x] Budget Histogram（按 `budget_usd` 分桶，固定区间）
  - [x] Top Events（先用 `commerce_jobs` 快照实现：max_paid/max_budget）

## 7. 风险与降级

- [ ] 风险：charts 聚合开销大（全量 include）
  - [ ] 降级：按 `include` 分批返回；或先 P0 只做 distribution + outcome_mix
- [ ] 风险：金额字段 float 精度
  - [ ] 处置：保持与现有 commerce 接口一致；必要时后续切换为 string/decimal（单独 spec）
