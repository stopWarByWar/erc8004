# ERC-8183 Commerce Stats API 执行清单

> 设计基线：`docs/designs/erc8183-commerce-stats.md`
> Spec 基线：`docs/specs/erc8183-commerce-stats-api.md`

本文是 `GET /agent/identity/commerce/stats` 接口的落地清单。

---

## 0. 验收口径

- [x] `GET /agent/identity/commerce/stats?uid=X` 返回 HTTP 200，JSON 结构符合 spec 定义
- [x] `action_breakdown`：无数据的 role 不出现，6 个 action 字段均存在（evaluator 固定返回 0）
- [x] `time_series`：三个窗口（24h/7d/30d）均存在，bucket 升序排列，`rejected_count` 仅统计 `job_rejected`
- [x] `time_series.success_rate`：`rejected_count` 仅统计 `job_rejected`（不含 expired），两者为 0 时为 0
- [x] `budget_distribution`：按 contract 分组，桶内 max_amount 非递减
- [x] `budget_distribution`：样本量 < 3 时不拆分 small/medium/large，直接返回 count + max_amount
- [x] `uid` 传非数字时返回 `code=1，msg="Invalid Request"`
- [x] uid 无数据时：`action_breakdown={}`，`time_series` 三窗口空数组，`budget_distribution={}`

## 1. Types 层

目标文件：`server/api/types/types.go`

新增以下类型：

- [x] `CommerceStats` — 顶层 stats 持有者（含 `ActionBreakdown`、`TimeSeriesStats`、`BudgetDistribution`）
- [x] `ActionBreakdown` — `map[string]ActionCounts`（key = provider/client/evaluator）
- [x] `ActionCounts` — 6 个 action 字段（`job_created`、`job_funded`、`job_submitted`、`job_completed`、`job_rejected`、`job_expired`）
- [x] `TimeSeriesStats` — 含 `Hours24`、`Days7`、`Days30` 三个 `[]TimeBucket`
- [x] `TimeBucket` — `Bucket`（int64）、`CompletedCount`（int）、`RejectedCount`（int）、`SuccessRate`（float64）
- [x] `BudgetDistribution` — `map[string]map[string]ContractBudgetStats`（第一层 key=role，第二层 key=contract）
- [x] `ContractBudgetStats` — `TotalCount`（int）、`Buckets`（`BudgetBuckets`）
- [x] `BudgetBuckets` — `Small`、`Medium`、`Large`（均为 `*BudgetBucketStat`，可空）
- [x] `BudgetBucketStat` — `Count`（int）、`MaxAmount`（string）
- [x] **样本量 < 3 的扁平桶**：`Buckets` 也可为 `map[string]interface{}{"count":, "max_amount":}`（当终态 job < 3 时使用）

## 2. Model 层

目标文件：`model/commerce.go`

### 2.1 新增聚合结构

- [x] `TimeBucketAgg` — `BucketTime uint64`、`CompletedCount int`、`RejectedCount int`、`SuccessRate float64`
- [x] `ContractBudgetAgg` — `Role`、`Contract`、`TotalCount`、`SmallCount`、`SmallMax`、`MediumCount`、`MediumMax`、`LargeCount`、`LargeMax float64`

### 2.2 新增查询函数

- [x] `GetCommerceActionCountsByRole(uid uint64)` → `map[string]map[string]int`
  - SQL：`SELECT role, action, COUNT(*) FROM commerce_actions WHERE agent_uid = ? GROUP BY role, action`
  - 返回：嵌套 map，role → action → count

- [x] `GetCommerceTimeSeries(uid uint64, windowStart, windowEnd, bucketDuration uint64)` → `[]TimeBucketAgg`
  - SQL：`(block_timestamp / bucketDuration) * bucketDuration` 作为 bucket_key，按 bucket 分组 SUM completed/rejected
  - 利用现有索引：`idx_ca_agent_timestamp (agent_uid, block_timestamp)`
  - `rejected_count` 仅统计 `job_rejected`（不含 `job_expired`）

- [x] `GetCommerceBudgetItems(uid uint64)` → `[]RawBudgetItem` — model 层返回原始终态 budget 列表，percentile 计算由 logic 层实现

## 3. Logic 层

目标文件：`server/api/logic/commerceLogic.go`

- [x] `CommerceStatsParams` struct — `UID uint64`、`Now uint64`
- [x] `GetCommerceStats(CommerceStatsParams)` → `*types.CommerceStats`
  - 调用 `GetCommerceActionCountsByRole`
  - 计算三个窗口的起止时间，调用 `GetCommerceTimeSeries`
  - 调用 `GetCommerceBudgetItems` 并在 logic 层计算百分位数分桶（33rd/66th percentile）
  - 样本量 < 3 时构建扁平桶结构（无 small/medium/large 分层）
  - 过滤空 role（无数据的 role 不出现在返回中）

---

## 4. Handler 层

目标文件：`server/api/handle/commerceHandle.go`

- [x] `GetCommerceStatsHandler`
  - 解析 `uid`（uint64），非法时返回 `code=1，msg="Invalid Request"`
  - 查询该 agent 最新 `block_timestamp`（`GetLatestCommerceActionTimestampByUID`），若无则 fallback 到系统时间
  - 构建 `CommerceStatsParams` 并调用 `logic.GetCommerceStats`
  - 错误时返回 `code=1，msg="Internal Error"`
  - 成功时返回 `SuccessResp(gin.H{"stats": stats}, c)`

---

## 5. Router 层

目标文件：`server/api/router.go`

- [x] `r.GET("agent/identity/commerce/stats", handle.GetCommerceStatsHandler)`

## 6. 测试与验证

- [x] `go build ./server/main.go` — 编译通过
- [x] `go test ./...` — 现有测试通过（agentCard 外部 API 403 为预存问题，非本次修改引入）
- [ ] 手动测试：
  - `curl "http://localhost:8080/agent/identity/commerce/stats?uid=1"` 返回合法 JSON
  - 无数据 uid 返回 `action_breakdown={}`，`time_series` 三窗口空数组，`budget_distribution={}`
  - `uid=invalid` 返回 `code=1，msg="Invalid Request"`
- [ ] 边界测试：
  - 某 role 有部分 action（如只有 completed/rejected）：action_breakdown 只出现有数据的 action，其余字段存在但为 0
  - 时间窗口无数据：数组为空 `[]`
  - 样本量 < 3 的 contract：扁平桶结构（无 small/medium/large 分层）
  - `rejected_count` 不包含 expired：`time_series.success_rate` 计算只基于 job_completed + job_rejected
