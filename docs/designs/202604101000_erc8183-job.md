# ERC-8183 Commerce Job设计

> 状态：Draft
> 创建日期：2026-04-10
> 关联规范：[ERC-8183 Agentic Commerce](../erc-8183/erc-8183.md)

---

## 一、背景与目标

当前 `commerce_actions` 是事件驱动的设计，每条记录是一个 Job 生命周期中的单个动作（Created/Funded/Submitted/Completed 等）。这导致：

- 无法方便地查询一个 Job 的完整状态
- 未完成的 Job（Open/Funded/Submitted）信息分散

本设计目标：**新增 `commerce_jobs` 表，记录所有 Job 的实时状态**（每次事件都更新对应字段），支持查询任意 Job 的当前状态。

// UpsertCommerceJob 插入或更新 Job 记录
func UpsertCommerceJob(job *CommerceJob) error {
    if job == nil {
        return errors.New("nil job")
    }
    // UpdatedAt 必须为链上时间（block_timestamp）
    // 若 UpdatedAt = 0 直接返回 error（避免混入系统时间导致统计口径不一致）
    return db.Clauses(clause.OnConflict{
        Columns:   []clause.Column{{Name: "chain_id"}, {Name: "commerce_contract"}, {Name: "job_id"}},
        DoUpdates: clause.AssignmentColumns([]string{
            "client", "provider", "evaluator", "description",
            "budget", "budget_usd",
            "paid_amount", "paid_amount_usd",
            "platform_fee_amount", "platform_fee_usd",
            "evaluator_fee_amount", "evaluator_fee_usd",
            "payment_token", "token_symbol", "status", "hook_address",
            "expired_at", "submitted_at", "completed_at",
            "latest_action_uid", "latest_block_number", "latest_tx_hash", "updated_at",
        }),
    }).Create(job).Error
}

// FetchOrCreateCommerceJob 根据 chain_id + contract + job_id 查找或创建 Job
func FetchOrCreateCommerceJob(chainID, contract string, jobID uint64) (*CommerceJob, error) {
    var job CommerceJob
    err := db.Where("chain_id = ? AND commerce_contract = ? AND job_id = ?", chainID, contract, jobID).First(&job)
    if errors.Is(err, gorm.ErrRecordNotFound) {
        return &CommerceJob{
            ChainID:          chainID,
            CommerceContract: contract,
            JobID:            jobID,
            Status:           "open",
        }, nil
    }
    if err != nil {
        return nil, err
    }
    return &job, nil
}

## 四、索引器变更

### 4.1 核心逻辑

每个事件的 handler 处理流程：

1. 解析事件
2. 调用 `FetchOrCreateCommerceJob` 获取/创建 Job 记录
3. 根据事件类型**实时更新** Job 的所有相关字段
4. 调用 `UpsertCommerceJob` 保存

### 4.2 事件 → 字段更新映射


| 事件               | 更新的 Job 字段                                                 |
| ---------------- | ---------------------------------------------------------- |
| JobCreated       | 初始化 Job，status=open, client, hook, expired_at, description |
| ProviderSet      | provider, evaluator                                        |
| BudgetSet        | budget, payment_token, token_symbol, budget_usd            |
| JobFunded        | status=funded                                              |
| JobSubmitted     | status=submitted, submitted_at                             |
| JobCompleted     | status=completed, completed_at                             |
| PaymentReleased  | paid_amount, paid_amount_usd                               |
| PlatformFeePaid  | platform_fee_amount, platform_fee_usd                      |
| EvaluatorFeePaid | evaluator_fee_amount, evaluator_fee_usd                    |
| JobRejected      | status=rejected                                            |
| JobExpired       | status=expired                                             |


### 4.3 Paid/Fee 获取（避免调用 receipt，降低 RPC）

结算拆分来自合约在 `complete()` 中 emit 的 3 个事件（均可直接 FilterLogs 获取，无需 `eth_getTransactionReceipt`）：

- `PaymentReleased(jobId, provider, amount)`：provider 实收（net）
- `PlatformFeePaid(jobId, treasury, amount)`：平台费
- `EvaluatorFeePaid(jobId, evaluator, amount)`：评审费

USD 换算使用 **链上时间**：以事件所在 log 的 `block_timestamp` 调用历史价格换算（如 `GetHistoricalUSDBudget(..., blockTimestamp)`）。

## 五、UI：Job Detail / Job List（已实现口径对齐）

### 5.1 Job Detail 页面（信息架构与字段放置）

> 目标：默认首屏“概览可读”，同时能下钻到“链上证据可验证”。适配混合用户（外部/运营/开发者）。

#### Header（吸顶摘要条，P0）

- 标识：`chain_id`、`commerce_contract`（可复制/外链）、`job_id`
- 状态：`status`（以 `commerce_jobs.status` 为准）
- 时间：`updated_at`（on-chain block_timestamp，用于“最后更新”）
- 主金额：`token_symbol` + `budget`（同时显示 `budget_usd`）
- 快捷入口：
  - `ViewInFeed`：跳转到全局活动流并过滤/定位该 job
  - `ViewTimeline`：滚动到时间线证据区

#### 概览区（P0）

- 参与者（ParticipantsCard）
  - Client：`client`（地址截断 + 复制 + 外链）
  - Provider：`provider`（未设置时显示 `—`）
  - Evaluator：`evaluator`
  - 可选展示：若可解析 ERC-8004 身份，则提供“跳转 Agent 主页”入口（P1）
- 资金与费用拆分（MoneyCard）
  - Budget：`budget` + `budget_usd`（BudgetSet 时刻估值）
  - Paid（Provider net）：`paid_amount` + `paid_amount_usd`（PaymentReleased，complete 时刻估值）
  - Fees：
    - Platform：`platform_fee_amount` + `platform_fee_usd`（PlatformFeePaid）
    - Evaluator：`evaluator_fee_amount` + `evaluator_fee_usd`（EvaluatorFeePaid）
  - 展示规则：若 `status != completed`，Paid/Fee 显示为 `—`（或 0 且注明“完成后产生”）
- 信号/可信度（SignalsCard）
  - `signal_certainty`（definitive/indicative）、`signal_polarity`、`signal_weight`
  - 交互：点击跳转到该 job 在活动流中对应的证据事件

#### 溯源区（P1，默认折叠/可展开）

- 时间线（Timeline）
  - 垂直时间轴，按 `block_timestamp ASC` 排序
  - indicative 弱化（低对比），支持“仅 definitive”切换
  - 节点信息：action 图标、role、变化摘要、tx 外链
- 原始事件表（EventsTable）
  - 字段：`block_timestamp`、`action/event`、`role`、`tx_hash`、`log_index`
  - 按事件类型显示金额字段（BudgetSet/Paid/Fee/Refund 等）

#### 字段来源（Snapshot vs Evidence）

- 概览区（默认用快照表）：`commerce_jobs`
- 证据区（时间线/事件表）：`commerce_actions` + 结算事件（PaymentReleased/PlatformFeePaid/EvaluatorFeePaid）
- 时间展示：全部使用 on-chain 时间戳（`block_timestamp` 或合约字段，如 `expired_at/submitted_at/completed_at`）

#### 关键展示口径（避免歧义）

- `budget_usd`：BudgetSet 时刻的 USD（不是实时汇率）
- `paid_amount(_usd)`：provider 实收净额（net），来自 `PaymentReleased.amount`
- fee 字段：分别来自 `PlatformFeePaid.amount` / `EvaluatorFeePaid.amount`

### 5.2 Job List 页面（字段与布局建议）

> 目标：在不进入单个 Job Detail 的前提下，完成发现/筛选/对比；并在列表顶部展示“当前筛选范围”的概览指标（Filter-aware）。

#### 列表行（P0，建议每行 ≤ 8 个锚点）

- 定位：`chain_id`、`commerce_contract`、`job_id`
- 状态：`status`
- 金额：`token_symbol` + `budget`（可带 `budget_usd` 小字）
- 结算：`paid_amount_usd`（仅 completed；其他状态显示 `—`）
- 时间：`updated_at`（on-chain，用于默认排序）
- 角色视角（仅 Agent detail job list）：`role` + `counterparty`（对手方）

### 5.3 Job List：Jobs General 信息

**口径**：

- 指标随筛选变化（chain/contract/status/token/金额/时间）
- 时间基准：on-chain（主要用 `updated_at`）

**Summary Bar（P0，第一行，最多 6 张卡）**：

1. Jobs（Count）：`COUNT(*)`
2. Paid Volume (USD)：`SUM(paid_amount_usd)`（completed 有意义）
3. Budget Volume (USD)：`SUM(budget_usd)`（BudgetSet 时刻估值）
4. Outcome Mix：completed/rejected/expired 分布
5. Active：open/funded/submitted 分布或合计
6. Last Updated：`MAX(updated_at)`

**Distribution Row（P1，可折叠）**：

- Token 分布：按 `token_symbol` 聚合（paid/budget/job_count）
- Chain/Contract 分布：按 `chain_id + commerce_contract` 聚合
- Fees 分布（可选）：platform/evaluator fee（completed 多时展示）

**交互**：

- 卡片/分布点击即加筛选并刷新列表：
  - Paid Volume → `status=completed`
  - Outcome 某段 → `status=<segment>`
  - Active → `status in (open,funded,submitted)`
  - Token → `token_symbol=<token>`
  - Contract → `chain_id=<x>&commerce_contract=<y>`
- 明确提示：“指标随筛选变化”

### 5.4 图表体系：多维度展示 ERC-8183 数据（Charts Gallery）

> 目标：用可视化从多个维度解释 ERC-8183 的活跃度、规模、健康度与结构，并支持从图表下钻到 Job List / Job Detail / Activity Feed（证据）。要求图标表达“语义”，不是装饰。

#### 5.4.1 维度与指标矩阵（先定“看什么”）

- 时间维度：`updated_at` / `block_timestamp`（on-chain），窗口：24h / 3d / 7d / 1month / all / 自定义
- 状态维度：`status`（open/funded/submitted/completed/rejected/expired）
- 角色维度：client / provider / evaluator（若在 agent detail 范围内）
- Token 维度：`token_symbol` / `payment_token`
- 链与合约维度：`chain_id` + `commerce_contract`
- 金额维度：
  - Budget（承诺规模）：`budget` / `budget_usd`
  - Paid（实际净支付）：`paid_amount` / `paid_amount_usd`
  - Fee（平台/评审）：`platform_fee_usd` / `evaluator_fee_usd`

#### 5.4.2 图表集合（按“回答的问题”分组）

##### A) 活跃度（Activity）

1) Actions Over Time（柱状/折线）

- 含义：某时间桶内发生的事件/动作数量（可按 action 分堆叠）
- 下钻：点击桶 → Activity Feed（时间窗定位）

2) Active Jobs Over Time（折线）

- 含义：某时间桶内“有更新”的 job 数（以 on-chain 时间落桶）
- 下钻：点击桶 → Job List（时间窗过滤）

3) Created Jobs Over Time（折线/柱状）

- 含义：某时间桶内新创建的 job 数（以 `JobCreated` 的 on-chain 时间落桶）
- 下钻：点击桶 → Job List（时间窗过滤）

4) Unique Clients / Providers Over Time（双折线/分面）

- 含义：某时间桶内活跃的独立 client / provider 地址数（桶内去重计数）
- 下钻：点击桶 → Job List（时间窗过滤；可选附加 role 视角）

##### B) 健康度（Health）

3) Outcome Mix（环形/堆叠条）

- 含义：completed / rejected / expired 的占比（终态健康度）
- 下钻：点击 segment → Job List（`status=<segment>`）

4) Funnel：Open → Funded → Submitted → Completed（漏斗）

- 含义：从创建到完成的“转化路径”
- 下钻：点击层级 → Job List（`status=<layer>`）

##### C) 规模（Volume & Fees）

5) Paid Volume (USD) Over Time（折线）

- 含义：完成结算带来的净支付规模趋势（`paid_amount_usd`）
- 下钻：点击桶 → Job List（`status=completed` + 时间窗）

6) Platform Fee (USD) Over Time（折线）

- 含义：平台手续费发生额趋势（`platform_fee_usd`，按事件发生时间分桶）
- 下钻：点击桶 → Job List（`status=completed` + 时间窗）

7) Budget vs Paid（并列柱/双轴）

- 含义：承诺规模（`budget_usd`）与实际净支付（`paid_amount_usd`）差距
- 下钻：点击 → Job List（带时间窗或 token 过滤）

8) Fees Breakdown（堆叠条/环形）

- 含义：`platform_fee_usd` 与 `evaluator_fee_usd` 的结构占比
- 下钻：点击 segment → Job List（`status=completed` + fee 维度筛选）

##### D) 结构（Distribution / Composition）

9) Token Distribution（条形 Top N）

- 含义：按 token 聚合的 paid/budget 规模
- 下钻：点击 token → Job List（`token_symbol=...`）

10) Chain/Contract Distribution（条形 / treemap）

- 含义：不同链/合约的活跃度与规模（jobs_count / paid_usd）
- 下钻：点击 → Job List（`chain_id` + `commerce_contract`）

11) Budget Histogram（直方图，按 token 分组）

- 含义：金额分布（小额/中额/大额），用于识别异常大额 job
- 下钻：点击区间 → Job List（`min/max_budget(_usd)`）

##### E) 证据与溯源（Evidence）

12) Top Events（列表型图表）

- 含义：在某时间窗内 Top N 事件（最大 paid、最大 budget 变更、最多 rejected 等）
- 下钻：点击条目 → Job Detail（高亮对应事件/时间线定位）

#### 5.4.3 图标语义（必须“有意义”）

规则：图标表达“语义分类”，颜色表达“结果/风险”，形状表达“事件类型”。

- Status 图标（状态/漏斗/分布）
  - `open`：待办/空心圆
  - `funded`：锁/金库
  - `submitted`：上传/收件箱
  - `completed`：对勾
  - `rejected`：叉/禁止
  - `expired`：时钟
- Money 图标（规模/费用/对比）
  - `budget`：标签/票据
  - `paid`：转账箭头
  - `platform_fee`：收据/手续费
  - `evaluator_fee`：天平/徽章
- Dimension 图标（分布图标题/legend）
  - token：硬币
  - chain：链环/网络
  - contract：文档/合约
  - time：时钟

> 约束：同一语义全站复用同一图标；不要用同一颜色代表不同语义。

#### 5.4.4 Drill-down（统一交互）

- 任意图表点击必须能跳到：
  - Job List（带 filters + 时间窗），或
  - Activity Feed（带 filters + 定位），或
  - Job Detail（高亮对应事件）
- 时间序列图的桶点击：必须返回 `start_time/end_time`，金额类可附带 `status=completed`。
- 页面显式展示“当前 filters”（可复制分享）。

#### 5.4.5 空态与可靠性

- 无 USD：显示 `—` + tooltip“价格源不可用”
- 非 completed 的 paid/fee：显示 `—`（避免误导为 0）
- 样本不足：显示“样本不足”提示，避免用户过度解读趋势
