1. 目标与定位

在 ERC-8004 的链上 NewFeedback 事件之上，构建一个可供 链上其他合约消费 的 Credit Score。要同时输出：

  • per-tag 的子分：每个 tag1 一个 score
  • agent 级综合分：用于支付授信、permissioning、agent bank 评级
使用场景

未来 Agent Profile 直接消费 score + confidence + tag breakdown；
未来 Agent Bank 用 credit_score × confidence 做综合授信， 与 commerce_score、validation_pass_rate 一起加权融合。

对外数值约定：

  • score：numeric(6,4)，范围 [0, 1]，和 commerce 一致
  • confidence：numeric(4,2)，范围 [0, 1]
0 差
1 好

2. 核心约束（决定一切）

硬约束

我们不是协议官方。 tag 是用户随意填写的字符串，value 的语义无法预先约定。

这意味着：

  • ❌ 不能维护 tag schema（注册表、白名单）
  • ❌ 不能假设 value 的方向（越大越好 vs 越小越好）
  • ❌ 不能假设 value 的量纲（0~1？毫秒？美元？星级？）
  • ❌ 同名 tag 在不同人手里语义可能完全不同（"accuracy" 一个人写 0.95，另一个写 95）
推论

任何 依赖 value 语义 的聚合都不可靠。
Credit score 必须有一部分 完全不碰 value 含义 也能算。

3. 现状与缺陷

现有 feedback_tag_scores 表 + Postgres 触发器：

// 每来一条 feedback：
new_score = (old_score × old_count + new_format_value) / (old_count + 1)

缺陷一览：

问题表现
简单算术平均同一 client 多次刷好评等权累加
无时间衰减三年前的反馈和今天权重相同
无评分人权重零信誉账号和资深 client 等权，sybil 成本 ≈ 0
无置信度1 条 5 分 ≡ 100 条 5 分，对外都是 5 分
无综合分只有 per-tag，没有 agent 级总分
tag2 没用副标签只存表，不参与任何计算
分布信息丢失5×1分 与 5×5分 均值都是 3，方差信号不见
无负面非对称差评和好评对称，不符合真实信任建模

4. 设计：双层 Credit

把 credit 拆成 两层： 第一层完全不碰 value 语义，第二层只在 value 看起来"像评分"时才启动。

Layer A
Behavioral Credit

始终计算，不依赖 value 语义。

只看：谁评了、什么时候、撤没撤、多少独立人评、跨多少 tag。

抗 sybil 主力。

Layer B
Sentiment Credit

自适应启用。

当某 (agent, tag) 下的 value 看起来像在 [-1,1] 区间评分时，才把它当 sentiment 处理。

否则当作 profile 上的"参数分布"展示，不入 credit。

整体管线

IN NewFeedback 事件 + reviewer 行为
▼
① 每条 feedback 算 w = reviewer_weight × time_decay × dedupe_factor
▼
A Behavioral 信号：unique reviewer 加权数 / 撤销率 / client 分散度 / cross-tag breadth
B Sentiment 检测：判断 (agent,tag) 的 value 是不是评分。是则归一化加权平均；否则跳过。
▼
② Tag-level：tag_score + tag_authority（自适应权重）+ tag_confidence
▼
③ Agent-level：credit_score = α × A + (1−α) × Σ tag_sentiment × authority
▼
OUT credit_score ∈ [0,1] + confidence ∈ [0,1] + per-tag breakdown

5. Layer A — Behavioral Credit value-agnostic

不看 value 大小、不看 tag 含义，只看"谁、什么时候、对谁、撤没撤"。

单条 feedback 权重

wi = reviewer_weight × time_decay × dedupe_factor
因子计算说明
reviewer_weight 0.3 + 0.7 × min(1, completed_jobs / 20) 从 commerce_score_global 借力。零历史 → 0.1；已识别 sybil → 0。
time_decay 0.5 ^ ((now − ts) / 180d) 半衰期 180 天。可调。
dedupe_factor 0.5 ^ (k − 1) 同 reviewer 对同 (agent,tag) 第 k 次评分的权重。

revoked = true 的反馈不进入加权（但 会被记入 revocation_rate）。

Behavioral Score 公式

R = Σ wunique-reviewer // 加权后的有效独立评审人数
revocation_rate = revoked_count / total_count
diversity = 1 − HHI(reviewer_volume) // 0~1，越分散越接近 1

A = σ(log(1+R)) × (1−revocation_rate) × diversity

σ(x) = x / (x + 3)，一个简洁的 saturation。
R = 0 → A ≈ 0；R = 10 → A ≈ 0.78 × …。

6. Layer B — Sentiment Credit adaptive

核心创新：不预注册 tag schema，而是运行时判断这个 (agent, tag) 的 value 是不是评分。

Sentiment 自适应检测

触发条件 — 全部满足

设该 (agent, tag) 下所有未撤销 feedback 的 value 集合为 V，

  • |V| ≥ 3 — 至少 3 条样本
  • median(|v|) ≤ 1.0 — 中位绝对值落在 [-1, 1] 区间
  • max(|v|) ≤ 2.0 — 没有出现 999 / 12345 这种"参数"
  • stddev(V) ≤ 1.0 — 离散度合理

人话：这个 (agent, tag) 下大家都在 [-1, 1] 老老实实打分 → 当 sentiment 处理；
有人写延迟毫秒（850） → 这个 tag 自动被排除出 sentiment，进入 profile 原始展示。

归一化 + 负面非对称

// 已知 v ∈ [-1, 1]
ni = clamp((vi + 1) / 2, 0, 1) // 映射到 [0, 1]

// 差评轻度放大（不夸张）
if ni < 0.4: nieff = 0.4 − (0.4 − ni) × 1.3
else: nieff = ni

反恶意单 reviewer 上限

单个 reviewer 对同一 agent 的负贡献累计权重上限 ≤ 0.15， 防止单一恶意账号搞垮某个 agent。

Tag-level Sentiment 分数

tag_sentiment = Σ(nieff × wi) / Σ(wi)
tag_confidence = min(1, Σ wunique-reviewer / 10)

7. Tag Authority — 自适应权重

既然不能预注册 tag，那么每个 tag 在综合分里的权重不是预设的，是从数据本身推出来的。

tag_authority = log(1 + unique_reviewer_count)
× min(1, time_active_days / 30)
× (1 − newcomer_dominance)
直觉

多人评、评了一段时间、不是新号刷出来 的 tag，自动在综合分里占更高权重。
一个被 1 个人在 i_love_this 上刷了 100 条的 tag → 极低 authority → 不 dominate 综合分。

因子含义
log(1 + unique_reviewer_count)独立评分人数越多，tag 越可信。log 防爆炸。
time_active_days / 3030 天内才出现的新 tag 权重打折，防止短期刷量。
1 − newcomer_dominance"newcomer reviewer 占比"，过高则 authority 大幅下降。

8. 最终融合

Sentiment 综合（跨 tag）

B = Σ tag_sentimenti × tag_authorityi × tag_confidencei
    / Σ tag_authorityi × tag_confidencei

最终 credit_score

credit_score = α × A + (1 − α) × B
场景α说明
有 sentiment-eligible tag0.4情感为主，行为兜底。
完全没有 sentiment tag1.0退化为纯行为信号。
新 agent / 反馈极少（R < 1）credit_score = NULL不出分，让消费方决定 fallback。

overall confidence

confidence = clamp(Σ wunique-reviewer / 10, 0, 1)

10. 已决策事项

  1. 用途：链上消费 → 严格 [0,1] + confidence，所有公式都要可链上低开销复算，并保证 monotonic
  2. 粒度：per-tag + 综合分都要 → 数据模型分两张表：feedback_tag_scores_v2 + feedback_credit_scores
  3. 反作弊：中等强度 → reviewer_weight + dedupe + time_decay + tag_authority + Layer A 撤销率
  4. 负面非对称：要，但不夸张 → 差评轻放大 1.3 倍 + 单 reviewer 负贡献上限 0.15
  5. 标度：和 commerce 一致 → numeric(6,4) 范围 [0,1]，confidence numeric(4,2)
  6. tag schema：不能注册 → 完全自适应：sentiment 检测 + tag_authority 都从数据推
  7. 未识别为 sentiment 的 tag → 仅 profile 展示 value 原始分布（min/p50/p95/max），不入 credit
  8. reviewer_weight 数据源 → 起步只用 commerce_score_global + identity 持有，避开 feedback→feedback 的递归依赖
  9. 时间衰减半衰期 → 180 天起步，agent bank 接入时可调到 90 天
  10. 冷启动策略 → credit_score = NULL，由消费方决定 fallback（不强制给 0.5 "中性"）
  11. α 策略 → 有 sentiment tag 时 0.4；没有时退化为 1.0（纯行为信号）
  12. revocation 处理 → 不进 Layer B 计算；但计入 Layer A 的 revocation_rate（影响 behavioral）

PHASE 1
